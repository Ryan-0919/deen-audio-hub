# 书籍型题库系统设计文档

## 1. 目标定义

本次要新增的不是一套新的机考系统，也不是一套新的批改系统，而是一套独立的书籍型题库系统。

该系统主要服务于以下产品场景：

1. 已购买《300小案例》的用户，可以在平台内进行对应题目的电子化练习。
2. 已购买《主观近8年真题》的用户，可以在平台内进行对应题目的电子化练习。
3. 用户做题后可以查看参考答案、解析、音频微课，但不进入任何 AI 批改或人工批改流程。
4. 该系统定位为“练题系统”，不是“考试系统”。

一句话概括：

`书籍 = 一个题库产品，用户购买的是整本书的练习权限。`

## 2. 产品定位

### 2.1 和现有模块的关系

当前平台已有以下模块：

1. 音频课程
2. 视频课程
3. 机考系统
4. 主观批改
5. 法条检索
6. 打字练习

新题库系统建议作为独立模块存在：

1. 前台新增入口：`我的题库`
2. 后台新增入口：`题库产品管理`

它与现有机考系统的关系如下：

1. 可以复用机考系统现有的做题交互能力。
2. 不复用机考系统的考试定位。
3. 不进入批改队列。
4. 不进入考试排行榜。
5. 不走考试次数、批改次数、交卷结果、考试记录这一套逻辑。

### 2.2 题库系统的核心价值

这套系统主要解决的是纸质书配套电子练习的问题。

用户最核心的需求不是“模拟考试”，而是：

1. 随时找到对应书籍中的题
2. 按科目持续练题
3. 保存做到哪里
4. 做完后马上看参考答案
5. 有音频微课的题可以继续听讲解
6. 对题目做状态管理，如“已掌握”“待重做”

## 3. 书籍题库产品结构

### 3.1 第一阶段题库产品

第一阶段先支持两本书：

1. `300小案例`
2. `主观近8年真题`

### 3.2 前台展示结构

前台不展示“试卷”概念，而展示“书籍题库”概念。

推荐结构如下：

1. 我的题库
2. 书籍详情页
3. 题目练习页

### 3.3 两本书的组织方式

#### 300小案例

推荐结构：

`书籍 -> 科目 -> 题目`

例如：

1. 民法
2. 刑法
3. 民诉
4. 刑诉

#### 主观近8年真题

推荐结构：

`书籍 -> 科目 -> 题目`

注意：

1. 不按年份做主分类
2. 年份只作为题目属性、标签、筛选项存在

这样做的好处：

1. 后续新增第 9 年、第 10 年真题时无需重构目录
2. 用户更符合按科目专项刷题的习惯
3. 与《300小案例》的使用结构保持统一

## 4. 前台页面设计

## 4.1 我的题库

该页面是用户进入题库系统的首页。

页面建议展示：

1. 已解锁的书籍列表
2. 每本书的封面
3. 每本书的简介
4. 总题数
5. 已作答题数
6. 已掌握题数
7. 待重做题数
8. 继续练习按钮

每本书卡片上建议保留一个核心入口：

`继续练习`

该按钮直接跳转到用户上次练习到的题目。

## 4.2 书籍详情页

用户点击一本书后进入书籍详情页。

页面建议分成三块：

### 顶部信息区

展示：

1. 书籍名称
2. 封面
3. 简介
4. 总题数
5. 已作答数量
6. 已查看答案数量
7. 已掌握数量
8. 待重做数量

### 中间导航区

按科目切换，例如：

1. 民法
2. 刑法
3. 民诉
4. 刑诉

### 下方题目列表区

每道题目建议展示以下信息：

1. 题号
2. 标题
3. 所属科目
4. 年份标签
5. 纸书页码
6. 是否有音频微课
7. 当前状态

状态建议包括：

1. 未做
2. 已作答
3. 已查看答案
4. 已掌握
5. 待重做

### 书籍详情页筛选项

建议支持：

1. 全部
2. 未做
3. 已作答
4. 已查看答案
5. 已掌握
6. 待重做

对于《主观近8年真题》，建议额外支持：

1. 按年份筛选

但年份只做筛选项，不做主分组结构。

## 4.3 题目练习页

题目练习页可以复用现有机考系统的一部分交互，但整体体验必须去考试化。

### 保留的能力

1. 左侧题号导航
2. 上一题 / 下一题
3. 自动保存草稿
4. 法条检索
5. 音频微课播放

### 去掉的考试化能力

1. 倒计时
2. 交卷按钮
3. 交卷确认弹窗
4. 批改中状态
5. 考试完成结果页
6. 准考证、考区、考试须知等考试元素

### 顶部建议显示内容

1. 书籍名
2. 当前科目
3. 当前题号
4. 本书进度
5. 当前状态

### 客观题交互

客观题流程建议为：

1. 用户作答
2. 自动保存
3. 用户点击 `查看答案`
4. 展示正确答案和解析
5. 用户点击 `已掌握` 或 `待重做`

### 主观题交互

主观题流程建议为：

1. 用户先自己作答
2. 自动保存草稿
3. 用户点击 `查看参考答案`
4. 展示参考答案、采分点、解析、音频微课
5. 用户自行判断并点击 `已掌握` 或 `待重做`

注意：

1. 该系统不提供 AI 批改
2. 该系统不展示得分
3. 该系统不进入人工批改

## 5. 用户体验提升建议

如果目标是提升纸书配套题库的使用体验，最重要的不是“评分”，而是“连续练习”和“复习效率”。

建议优先做好以下能力：

### 5.1 继续练习

每本书都要支持：

1. 记住上次做到哪一道题
2. 用户下次进入时可直接继续

### 5.2 题目状态管理

每道题建议支持以下状态：

1. 未做
2. 已作答
3. 已查看答案
4. 已掌握
5. 待重做

其中最重要的是：

1. 已掌握
2. 待重做

因为这两个状态能帮助用户构建个人复习路径。

### 5.3 只看待重做

建议在书籍详情页中增加快捷筛选：

1. 只看待重做
2. 只看未做
3. 只看已查看答案

### 5.4 纸书映射

每道题建议显示：

1. 对应书籍
2. 题号
3. 所属科目
4. 对应页码

这样用户可以在线上练题、线下翻书之间来回切换。

### 5.5 音频微课联动

如果题目存在音频微课，则在题目练习页直接显示音频播放器。

推荐位置：

1. 题干或案情下方
2. 参考答案区域上方

这样用户做完题可以立刻进入讲解，不需要再跳到其他模块。

## 6. 后台系统设计

## 6.1 后台新增模块

建议后台新增一个独立模块：

`题库产品管理`

该模块与现有 `题库管理`、`机考试卷管理` 分开。

建议包含以下页面：

1. 题库产品管理
2. 题库分类管理
3. 题库题目管理
4. 题库权限管理

## 6.2 题库产品管理

这里管理的是前台用户能看到的“书籍题库产品”。

例如：

1. 300小案例
2. 主观近8年真题

建议字段：

1. 名称
2. 封面
3. 简介
4. 排序
5. 是否上架

## 6.3 题库分类管理

这里管理的是题库产品下的分类。

第一阶段建议按科目分类，例如：

1. 民法
2. 刑法
3. 民诉
4. 刑诉

后续如有需要，也可以支持：

1. 章节
2. 专题
3. 小节

但第一阶段建议只做一级科目分类，保证结构清晰。

## 6.4 题库题目管理

后台这里用于：

1. 单题新增
2. 单题编辑
3. Excel 导入
4. 音频微课上传
5. 题目排序
6. 题目上下架

每道题建议维护这些字段：

1. 所属题库产品
2. 所属科目
3. 题号
4. 标题
5. 年份
6. 页码
7. 题型
8. 题干
9. 参考答案
10. 解析
11. 音频微课
12. 排序

## 6.5 题库权限管理

后台需要能按“整本书”给用户开权限。

建议权限粒度：

1. 用户 - 题库产品权限

不建议按题目粒度开权限，也不建议按单张试卷粒度开权限。

原因：

1. 运营成本高
2. 后续补题不方便
3. 不符合书籍型产品逻辑

## 7. 数据结构建议

## 7.1 现有能力可复用部分

当前系统已经有：

1. `QuestionBankFolder`
2. `QuestionBankItem`

它们已经可以承载题目内容本身，包括：

1. 题干
2. 解析
3. 参考答案
4. 音频微课
5. 客观题选项
6. 主观题分问

因此，题目内容本身建议继续复用现有题库表，不重新造一套题目模型。

## 7.2 建议新增的数据层

为了支持“书籍型题库产品”，建议新增一层独立结构，而不是继续复用考试用的 `MockExamPaper`。

推荐新增以下实体：

### 题库产品

表示一本书，例如：

1. 300小案例
2. 主观近8年真题

### 题库产品分类

表示一本书下的科目分类，例如：

1. 民法
2. 刑法
3. 民诉
4. 刑诉

### 题库产品题目映射

用于把现有 `QuestionBankItem` 挂到某一本书、某个科目下，并定义展示顺序。

### 用户题库产品权限

表示某个用户是否拥有某本书的使用权。

### 用户题库练习记录

记录用户在一本书中的练习进度，例如：

1. 上次练习到哪道题
2. 已完成多少题
3. 已掌握多少题
4. 待重做多少题

### 用户题库题目状态

记录某个用户对某道题的状态，例如：

1. 是否已作答
2. 是否已查看答案
3. 是否已掌握
4. 是否待重做
5. 最后一次作答内容

## 7.3 为什么不建议复用 MockExamPaper / MockExamRecord

不建议直接复用考试系统的 `MockExamPaper` 与 `MockExamRecord`。

原因如下：

1. 考试系统天然绑定考试感
2. 考试系统天然关联交卷、批改、分数、记录、排行榜
3. 一旦复用，会让题库系统再次和批改系统耦合
4. 题库练习更适合轻量、连续、随时进入退出的记录模式

因此建议：

1. 题目内容复用现有题库表
2. 用户练习记录单独走新链路

## 8. 权限设计

权限设计建议采用“整本书授权”模式。

即：

1. 用户购买《300小案例》，获得《300小案例》的全部题库权限
2. 用户购买《主观近8年真题》，获得《主观近8年真题》的全部题库权限

这样做有几个明显优点：

1. 后续新增题目时，老用户自动继承
2. 不需要每次新增题目后再去补权限
3. 更符合书籍销售逻辑
4. 更适合和商城商品绑定

## 9. 一期开发范围建议

为了尽快上线并验证效果，建议一期先做最核心的闭环。

### 一期建议做

1. 我的题库首页
2. 两本书的书籍详情页
3. 按科目浏览题目
4. 题目练习页
5. 自动保存作答内容
6. 查看答案 / 查看参考答案
7. 查看解析
8. 音频微课播放
9. 已掌握 / 待重做状态
10. 用户题库权限

### 一期暂不做

1. AI 批改
2. 人工批改
3. 排行榜
4. 错题本独立页
5. 收藏夹
6. 智能组题
7. 随机抽题
8. 按年份主分类

## 10. 二期增强方向

在一期跑通后，建议二期再考虑以下增强：

1. 错题本
2. 只看待重做
3. 题目收藏
4. 按年份筛选
5. 学习报告
6. 每科进度统计
7. 章节标签
8. 题目搜索

## 11. 数据库字段清单建议

本节用于把“书籍型题库系统”建议新增的数据结构收敛成可落地的表设计思路。

原则如下：

1. 题目内容本身尽量复用现有 `QuestionBankItem`
2. 书籍题库产品单独建表
3. 用户练习记录单独建表
4. 不与 `MockExamPaper`、`MockExamRecord` 混用

### 11.1 题库产品表

建议表名：

`BookQuestionBank`

建议字段：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `id` | string | 是 | 主键 |
| `name` | string | 是 | 题库产品名称，如《300小案例》 |
| `code` | string | 是 | 唯一编码，便于接口识别 |
| `coverUrl` | string | 否 | 封面图 |
| `coverObjectKey` | string | 否 | 封面 OSS Key |
| `description` | string | 否 | 简介 |
| `status` | enum | 是 | `draft` / `published` / `closed` |
| `sortOrder` | number | 是 | 排序 |
| `isVisible` | boolean | 是 | 前台是否可见 |
| `createdAt` | datetime | 否 | 创建时间 |
| `updatedAt` | datetime | 否 | 更新时间 |

建议第一批初始化两条：

1. `300_case_book`
2. `recent_subjective_real_questions`

### 11.2 题库产品科目表

建议表名：

`BookQuestionBankSubject`

建议字段：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `id` | string | 是 | 主键 |
| `bookId` | string | 是 | 所属题库产品 |
| `name` | string | 是 | 科目名，如民法 |
| `code` | string | 是 | 科目编码 |
| `sortOrder` | number | 是 | 排序 |
| `createdAt` | datetime | 否 | 创建时间 |
| `updatedAt` | datetime | 否 | 更新时间 |

说明：

1. 一本书下可以有多个科目
2. 第一阶段建议只做一级科目，不做树形层级

### 11.3 题库产品题目映射表

建议表名：

`BookQuestionBankItem`

该表作用是把现有 `QuestionBankItem` 组织成一本书中的具体题目。

建议字段：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `id` | string | 是 | 主键 |
| `bookId` | string | 是 | 所属题库产品 |
| `subjectId` | string | 是 | 所属科目 |
| `questionBankItemId` | string | 是 | 对应现有题库题目 ID |
| `title` | string | 否 | 前台展示标题，可覆盖原题标题 |
| `questionNo` | string | 否 | 题号，如 1、2、3 或 3-1 |
| `yearLabel` | string | 否 | 年份标签，如 2019 |
| `pageLabel` | string | 否 | 页码标签，如 P32 |
| `tagsJson` | string | 否 | 额外标签 |
| `sortOrder` | number | 是 | 展示顺序 |
| `status` | boolean | 是 | 是否上架 |
| `createdAt` | datetime | 否 | 创建时间 |
| `updatedAt` | datetime | 否 | 更新时间 |

说明：

1. 同一题理论上可以复用到不同书籍产品中
2. `QuestionBankItem` 负责内容，`BookQuestionBankItem` 负责前台组织和展示属性

### 11.4 用户题库产品权限表

建议表名：

`UserBookQuestionBankPermission`

建议字段：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `id` | string | 是 | 主键 |
| `userId` | string | 是 | 用户 ID |
| `bookId` | string | 是 | 题库产品 ID |
| `sourceType` | string | 否 | 权限来源，如 manual / shop_order |
| `sourceId` | string | 否 | 来源记录 ID |
| `createdAt` | datetime | 否 | 创建时间 |
| `updatedAt` | datetime | 否 | 更新时间 |

约束建议：

1. `userId + bookId` 唯一

### 11.5 用户题库练习记录表

建议表名：

`UserBookQuestionBankProgress`

建议字段：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `id` | string | 是 | 主键 |
| `userId` | string | 是 | 用户 ID |
| `bookId` | string | 是 | 题库产品 ID |
| `lastSubjectId` | string | 否 | 上次停留科目 |
| `lastBookItemId` | string | 否 | 上次练习到的题目 |
| `answeredCount` | number | 是 | 已作答题数 |
| `viewedAnswerCount` | number | 是 | 已查看答案题数 |
| `masteredCount` | number | 是 | 已掌握题数 |
| `redoCount` | number | 是 | 待重做题数 |
| `lastPracticedAt` | datetime | 否 | 最后练习时间 |
| `createdAt` | datetime | 否 | 创建时间 |
| `updatedAt` | datetime | 否 | 更新时间 |

说明：

1. 每个用户每本书一条总进度记录
2. 用于前台“继续练习”和概览统计

### 11.6 用户题目练习状态表

建议表名：

`UserBookQuestionBankItemState`

建议字段：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `id` | string | 是 | 主键 |
| `userId` | string | 是 | 用户 ID |
| `bookId` | string | 是 | 题库产品 ID |
| `bookItemId` | string | 是 | 书籍题目映射 ID |
| `questionBankItemId` | string | 是 | 对应原题 ID |
| `answerJson` | string | 否 | 用户答案 |
| `draftText` | string | 否 | 主观题草稿 |

约束建议：

## 15. 结论

本次新增题库系统，最适合的方案不是再复制一套考试系统，而是建设一套“书籍型数字题库系统”。

建议方向如下：

1. 前台新增独立入口：`我的题库`
2. 后台新增独立入口：`题库产品管理`
3. 产品按“整本书”组织，不按试卷组织
4. 题目按“科目”归类，不按“年份”归类
5. 年份只作为标签和筛选项
6. 题目内容复用现有题库结构
7. 用户练习记录走独立新链路
8. 不进入任何批改逻辑

第一阶段先落两本书：

1. `300小案例`
2. `主观近8年真题`

目标是让已购书用户在平台内拥有：

1. 可持续练题
2. 可查看答案
3. 可听音频讲解
4. 可管理题目掌握状态
5. 可随时回到上次练习位置

这套模式比“电子考试化”更贴合纸书配套使用场景，也更有利于长期扩展更多书籍型题库产品。
