# 商城数据库设计草案

## 1. 设计目标

本数据库设计用于在现有音频课程系统基础上新增统一商城能力，同时满足：

- 纯虚拟商品
- 纯实物商品
- 虚拟加实物组合商品

数据库设计遵循以下原则：

- 用户与课程复用现有表
- 商品、订单、履约、物流拆层设计
- 历史订单必须保留商品快照
- 课程权限仍复用现有 `UserCoursePermission`

## 2. 现有可复用模型

当前已有模型中，商城可以直接复用：

- `User`
- `Course`
- `UserCoursePermission`

说明：

- 用户购买课程类商品后，不需要新增一套课程权限表
- 支付成功后直接向 `UserCoursePermission` 写入数据即可

## 4. 商品中心模型

### 4.1 ShopCategory

用于商城分类。

建议字段：

- `id`
- `name`
- `sortOrder`
- `status`
- `createdAt`
- `updatedAt`

### 4.2 ShopProduct

用于商品主表。

建议字段：

- `id`
- `categoryId`
- `name`
- `subtitle`
- `coverUrl`
- `coverObjectKey`
- `type`
- `status`
- `description`
- `detailContent`
- `sortOrder`
- `salesCount`
- `requiresShipping`
- `isDeleted`
- `createdAt`
- `updatedAt`

说明：

- `requiresShipping` 对纯实物和组合商品为真
- `detailContent` 可存富文本或长文本

### 4.3 ShopProductImage

用于商品轮播图和详情图。

建议字段：

- `id`
- `productId`
- `imageUrl`
- `imageObjectKey`
- `sortOrder`
- `createdAt`

### 4.4 ShopProductCourse

用于商品和课程的绑定关系。

建议字段：

- `id`
- `productId`
- `courseId`
- `createdAt`

说明：

- 纯虚拟商品可绑定一个或多个课程
- 组合商品也可绑定课程
- 纯实物商品通常不绑定课程

### 4.5 ShopSku

用于商品售卖规格。

建议字段：

- `id`
- `productId`
- `name`
- `price`
- `originalPrice`
- `stock`
- `weight`
- `status`
- `isDefault`
- `createdAt`
- `updatedAt`

说明：

- 一期即使规格简单，也建议保留 SKU 层
- 后续扩展更方便

## 10. 关键关系

### 10.1 商品关系

- 一个分类下有多个商品
- 一个商品下有多个图片
- 一个商品下有多个 SKU
- 一个商品可绑定多个课程

### 10.2 订单关系

- 一个订单有多个订单明细
- 一个订单有多个支付记录
- 一个订单可有一个或多个数字履约记录
- 一个订单可有一个或多个发货记录

### 10.3 履约关系

- 一个订单明细可对应一个数字履约记录
- 一个订单明细也可对应一个发货明细
- 组合商品会同时产生数字履约和实物履约

## 11. 推荐约束

建议增加以下唯一约束和索引：

- `ShopCategory.name`
- `ShopOrder.orderNo`
- `ShopCartItem.userId + skuId`
- `ShopProductCourse.productId + courseId`
- `ShopShipment.orderId`

建议增加以下查询索引：

- `ShopProduct.categoryId + status + sortOrder`
- `ShopOrder.userId + createdAt`
- `ShopOrder.status + createdAt`
- `ShopDigitalFulfillment.status + createdAt`
- `ShopShipment.status + createdAt`

## 12. 与课程权限表的关系

课程类商品支付成功后的发放逻辑：

1. 读取商品绑定课程
2. 遍历课程列表
3. 向 `UserCoursePermission` 写入
4. 若已存在权限则跳过

这样可以直接复用现有学习系统，不需要再做商城专属权限表。
